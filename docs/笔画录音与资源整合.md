# 笔画录音与资源整合

2026-11-18。录音页在“拼音／笔画”之间切换，两种模式共用按住录音、技术检查、人工待重录、自动试听和播放中打断重录。本文定义数据隔离、导出格式和后续接入网站成品录音的边界。

## 清单与存储

- 笔画任务来自 `resources/stroke-audio-catalog.json` 的 31 个已解析名称，不新增或猜测笔画名称。
- 每项使用清单的 `stroke-<12 位哈希>` 作为永久身份，显示名称使用对应 `text`。位置编号仅用于展示和导出文件排序，不能代替 ID。
- 拼音继续使用 `reading`、原 IndexedDB 数据库、原位置键及原 ZIP 格式。
- 笔画使用独立的 `bishun-stroke-recorder` 数据库和 `bishun-stroke-recorder-current` 位置键，不与拼音录音、审核标记或进度混用。
- 两种模式的录音均只保存在当前浏览器。切换模式不会删除另一模式的录音。

## 笔画导出

ZIP 文件名为 `bishun-strokes-YYYY-MM-DD.zip`，包含 `manifest.json` 和实际浏览器编码的音频。清单顶层包含 `schemaVersion: 1`、`kind: "strokes"` 和 `recordings`。

```json
{
  "id": "stroke-f8c6e3e86baa",
  "text": "横",
  "file": "0009_stroke-f8c6e3e86baa_横.m4a",
  "durationMs": 1200,
  "mimeType": "audio/mp4;codecs=mp4a.40.2",
  "createdAt": "2026-11-18T08:00:00.000Z"
}
```

文件名包含位置、稳定 ID 和便于人工核对的名称。扩展名以实际编码为准，iOS 通常为 M4A/AAC，Chrome 通常为 WebM/Opus。拼音导出仍使用原来的 `reading` 字段和文件名，不增加 `kind` 字段。

## 后续整合规则

导出 ZIP 是待审核素材，不会自动替换网站现有 TTS 成品。整合时应：

1. 对照 `resources/stroke-audio-catalog.json` 校验每个 `id` 与 `text`，拒绝未知、重复或名称不匹配的条目，不能按数组位置套用录音。
2. 检查清单与文件一一对应，统一进行 Unicode 归一化后匹配文件名；逐段解码并检查时长、有效声、截断、响度和削波。
3. 人工确认每段录音只读出目标笔画名称，发音及首尾完整。技术检查通过不等于教学或试听审核通过。
4. 保留原始导出，在后期副本中裁剪和统一响度，再转换为网站使用的 MP3。不要在浏览器运行时转码。
5. 生成新的版本目录和完整清单，记录实际时长、字节数、SHA-256 和 `pending-listening` 状态；需要替换已确认文件时使用新版本并重新试听，不能沿用旧审核结论。
6. 只有全部必需名称都有对应资源且校验通过时才发布新清单。播放端升级需保留失败提示与取消规则，不能把缺失名称回退成其他笔画或浏览器语音。

现有 `public/audio/strokes/v1/` 与审核状态已保留；2026-11-18 的实际导入及 v2 切换见[用户自录音 v2 整合](用户自录音v2整合.md)。
