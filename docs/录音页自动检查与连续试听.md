# 录音页自动检查与连续试听

2026-11-14。目标是利用浏览器内已有的录音，快速筛查技术问题、连续试听并立即重录。本文是本次实现的行为约定，不表示所有录音已通过人工发音审核。

## 数据与兼容约束

- 继续使用 `docs/拼音音节合成列表.json` 的 `reading` 作为录音身份，不改变清单内容、排列和现有导出编号。
- 录音仍保存在 IndexedDB 的 `recordings` 对象仓库，键仍为 `reading`，已有音频不重写、不迁移、不删除。
- 数据库升级只增加 `reviews` 对象仓库。人工“待重录”标记及技术检查结果关联 `reading + 录音标识`；重录后旧结果失效，不套用到新录音。
- 刷新位置改为保存 `reading`；仍能读取此前保存的数字下标。存储不可用时只影响位置恢复，不影响录音。
- macOS 解压后部分文件名可能变成 NFD；导入或匹配文件时必须进行 NFC 归一化。本次不改变现有 ZIP 导出格式。

## 技术检查

录音由当前浏览器通过 Web Audio API 解码，PCM 计算完全在本机进行，不上传音频。当前录音优先检查；打开“管理与导出”后，其余已录项目按单个任务排队检查，避免同时解码全部录音。

页面将以下结果显示为“疑似问题”，不自动判废或删除录音：

- 解码失败；
- 总时长或有效发声时长过短；
- 没有超过检测阈值的发声窗口，疑似空录音；
- 首尾静音过长；
- 排除首尾静音后的有效声 RMS 响度过低；
- 峰值接近满刻度，或出现连续满刻度采样，疑似过响／削波。

RMS 使用 dBFS。静音窗口、响度和峰值阈值是筛查参数，不是普通话发音标准；AAC 解码过冲也不能单独证明原始录音削波。声母、韵母、声调和语境仍需人工试听。分析失败不影响原录音播放、重录和导出。

## 快速定位与标记

“管理与导出”提供以下范围：全部、已录、未录、待复查。待复查包括人工标记和当前录音的技术疑似问题；自动分析完成的项目不视为发音已审核。

- “下个未录”保持原有行为。
- 新增“下个待复查”，从当前项之后循环查找，保留每项的固定 `reading` 身份。
- “标记重录／取消待重录”只改变人工标记，不删除录音。
- 下拉框显示录音、人工标记和技术检查状态；完成后台检查后更新。

## 自动试听与立即重录

- 用户主动点击“自动试听”后，从当前已录项目开始播放；未录项目自动跳过。范围可选全部已录或待复查。
- 当前录音自然结束并等待短暂间隔后，才加载下一项。按钮可暂停；手动切项、筛选或开始录音会取消尚未执行的跳转。
- 播放中按住录音会停止当前音频、取消自动试听，并在原 `reading` 上开始重录，不先跳走。
- 新录音成功保存后仍停留在当前项，自动播放一次新录音供复查，不自动进入下一项。旧录音保留到新录音成功保存。
- 播放失败时停在当前项并明确提示，不静默跳过。浏览器自动播放限制需要由用户点击入口满足。
- 开始自动试听时释放麦克风；按住录音时再准备，避免部分手机的通话音频路由或播放衰减影响响度判断。
- 切后台停止播放、取消自动试听和定时器，按原规则丢弃未完成录音并释放麦克风；回前台不自动恢复连播。
- 所有加载、播放结束回调、延时跳转和保存共用操作代次。旧回调不得推进或修改新会话。

## 验证

自动回归覆盖 PCM 异常检测和既有录音导出。浏览器专项已覆盖自动推进、播放中重录、保存后原地复查、人工标记失效、数字位置兼容、后台取消和手机宽度；另以 v1 数据库实测升级保留原录音。后续回归重点包括：

- 自动试听自然推进、暂停和跳过未录；
- 播放中重录、保存后原地复查；
- 快速切项及过期播放回调不推进；
- 解码／播放失败停在当前项；
- 待复查筛选、人工标记及重录后失效；
- 数字位置兼容和按 `reading` 刷新恢复；
- 后台取消、手机布局、麦克风释放与重新准备。

仍需在 iPhone Safari 和实际使用的 Chrome 上试听，确认扬声器路由、音量和按住录音手感；自动检测不等于发音审核通过。
