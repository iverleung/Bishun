# Web 现状基线（W0）

日期：2026-11-08。代码基线：`9a7e181`，另含实施前已有的本站资源优先加载改动。此记录区分用户观察、代码分析、测试结果与尚未测量的项目。

## 1. 用户报告与复现路径

| 问题 | 手动复现任务 | 当前证据 |
|---|---|---|
| 语音不确定 | 开启声音，播放多笔字；后台返回后继续；切换浏览器 | 用户报告；代码使用 speechSynthesis，尚未做跨浏览器声音实测 |
| 字形加载波动 | 冷缓存查多个本站未收录字，模拟某 CDN 超时 | 用户报告；代码串行回退且无显式超时，尚无耗时分位数 |
| 乱序、跳动与音画不同步 | 播放中连点字卡、暂停继续、改输入、清空；观察读音与当前笔 | 用户报告；代码有分离播放入口、可变输入读取、逐字滚动与 bounce，尚未完成原站真机复现 |
| UI 与操作不友好 | 在手机查一组字，查第 N 笔，再切字；检查键盘遮挡 | 用户报告；当前界面无逐笔定位入口，移动端尺寸存在后置覆盖 |

旧工具入口、最多 20 字、单字／整组播放、速度与语音开关都需要在新版中有明确对应。逐笔定位、固定画布和教学节奏属于新增交互，不应只用新原型截图证明旧问题已修复。

## 2. 资源盘点

- `public/hanzi-writer-data/`：48 个 JSON，原始总计 74,120 字节，逐文件 zlib 压缩总计 34,937 字节（该值不是 HTTP gzip 或部署流量实测）。
- `test/data/`：工作区同样有 48 个 JSON，原始体积相同；路径与 medians 数量检查均一致。
- 开始实施时 fixture 仅 28 字已被 Git 跟踪，另 20 字被忽略；本阶段把本地已有的缺失 fixture 补入版本管理，避免换机器后静默缺数据。没有为此下载新 fixture。
- 上述 48 字不能证明全部汉字本地部署可行，也不能证明全部内容正确。候选全量字库的范围、许可、缺字、原始／压缩体积、部署文件限制与更新成本仍是 W2 待测项；按字请求与首屏全量下载必须区分。

## 3. 测试与构建基线

已使用锁文件安装依赖。Vite 6.4.1 生产构建通过，原站 JS 产物约 270.64 KB（gzip 116.58 KB）；这不是首屏网络、启动性能或音画同步指标。

实施前默认 npm test 指向 v2，页面使用 v3。直接运行 v3 得到 38/48 字和 220/233 笔与预期匹配，但旧 runner 返回 0，存在假通过。W0 已将默认测试改为只跑 v3，并修正失败返回码及 fixture 数量校验；同一组差异现在正确返回 1。

| 字 | 差异（既有测试预期 → v3 实际） |
|---|---|
| 山 | 第 2 笔：竖折 → 竖弯 |
| 小 | 第 2 笔：点 → 撇 |
| 水 | 第 2 笔：横撇 → 横钩 |
| 了 | 第 1 笔：横撇 → 横钩；第 2 笔：竖弯钩 → 竖钩 |
| 子 | 第 1 笔：横撇 → 横钩；第 2 笔：弯钩 → 竖钩 |
| 我 | 第 5 笔：斜钩 → 卧钩 |
| 字 | 第 4 笔：横撇 → 横钩；第 5 笔：弯钩 → 竖钩 |
| 吃 | 第 6 笔：横折弯钩 → 横斜钩 |
| 林 | 第 4 笔：捺 → 点 |
| 线 | 第 6 笔：斜钩 → 卧钩 |

这些是“测试预期与字典结果存在差异”，不是已经认定右侧全部错误。需按规范、字形上下文和有来源的名称表核验双方，再调整内容及回归。此次不修改预期使测试变绿。

不要使用裸 `node --test` 自动扫描本仓库：它还会执行 `test/download_data.js`，并把旧 runner 当成测试文件。应运行 package.json 明确指定的测试入口。
