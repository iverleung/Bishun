## 名称差异处理

W0 的 10 字差异同时包含旧预期问题和查询处理问题。此次没有全局选择多候选的首项或末项：仅对已核对字形的字增加逐笔修正，其他歧义保留未知；缺字／越界不再兜底为“点”。字典结果不是整库已经过教学审核的证明。

核对资料：仓库中的 [GF 0023—2020](../GF0023-2020《通用规范汉字笔顺规范》.pdf)（下述为 PDF 页序），以及教育部公开的 [GF 2001—2001 折笔规范](https://www.moe.gov.cn/ewebeditor/uploadfile/2015/01/12/20150112170016626.pdf)（PDF 第 9—10 页，印刷页 6—7 的笔形表）。后者扫描页已渲染并旋转查看；不能只依赖 OCR 或搜索摘要。

## 全量候选包盘点

固定候选版本为 `hanzi-writer-data@2.0.1`，从 npm 获取并锁定 integrity；单字原始 JSON 不修改，部署时连同未改动的 ARPHICPL.TXT 与来源说明复制。

- 单字文件 9,574 份，共 32,244,361 字节；逐文件 gzip 合计 14,421,114 字节。npm 压缩包 13,484,680 字节。两种压缩口径不同，不能混用为真实网络测量。
- 从本地 GF 0023 PDF 的 UCS 栏提取并检查 8,105 个唯一字符，候选包覆盖 6,866 字，缺 1,239 字；该包还包括规范表外字。不能声称覆盖全部规范汉字或所有 Unicode 汉字。
- 现有 48 份 fixture 与候选包同名字形 JSON 语义一致；原有 `public/hanzi-writer-data/` 内容保持不动。
- 全包静态部署、浏览器按字请求在体积上可行；目标托管服务的文件数和缓存策略尚未实机验证。资源许可与代码 MIT/ISC 声明独立，来源见 [HanziWriter 数据许可说明](https://hanziwriter.org/license.html)。

后续使用固定开发依赖与构建脚本生成资源，避免手工提交上万个数据副本。自托管不等于离线包或内容全审核，名称未知必须有可见的降级。

## 自托管资源与加载入口

- `hanzi-writer-data` 以精确版本开发依赖锁定。`npm run dev`／`npm run build` 的前置脚本生成 `public/characters/2.0.1/`，不需要运行时访问 npm 或公共 CDN。
- `resources:prepare` 逐文件检查路径、中心线、部首索引，原样复制 9,574 个 JSON，并生成 54,610 字节的轻量索引、独立 checksums、完整原许可和来源说明。索引不携带全部字形；检查明细按需用于离线校验。
- `resources:check` 重新核对全部生成文件、清单及许可。生成目录已忽略；部署使用构建后的 `dist/`，必须安装开发依赖后构建，不能直接部署未生成资源的 public 目录。
- `CharacterStore` 提供同源加载、共享 manifest、逐字缓存／去重、3 秒请求超时、调用方取消、HTTP 与 JSON 类型检查、笔数／中心线校验。取消一个调用方不影响其他调用方的共享请求。
- 名称完全缺失或存在未消歧项时保留 null，并标记 partial；名称有值但数量与字形不一致时拒绝返回就绪记录，不按索引强行拼接。目前发现棻（12/11）、濛（17/16）、皙（13/12）、脩（11/10）四个数量冲突，仍待专项核验。
- 通过实际 Vite HTTP 路径读取木、学、學，4 个请求（含一次 manifest）全部为本站地址。未收录字不会回落到外部 CDN。W2 当时尚未接入 UI；当前已由 W3 接入新版入口。

生成器当前 Node/zlib 的逐字 gzip 计数为 14,421,146 字节；上文初次 Python gzip 计数采用另一压缩实现／参数，32 字节差异不影响原始文件哈希与覆盖统计。两者都不是已测量的 HTTP 传输量。

## 预生成笔画录音

已从当前查询结果中明确可解析的笔画名生成 26 项稳定 ID 清单；未消歧的候选不生成确定读音。清单不是“全部官方笔形种类”的宣称。

- 制作工具锁定 edge-tts 7.3.1，普通话音色 `zh-CN-XiaoxiaoNeural`、语速 `-10%`。合成阶段需要网络，用户播放不需要请求该服务。
- 26 份 MP3 共 131,704 字节，处理后时长 429—1,183ms。采用保守首尾静音裁剪，不删除中间停顿；ffmpeg 全量解码、ffprobe 时长、文件长度与 SHA-256 校验通过。
- 成品和 `manifest.json` 位于 `public/audio/strokes/v1/`，清单记录 URL、文字、音色、语速、时长、字节数、哈希和 `pending-listening` 状态。**尚未完成人工逐条试听**，不能标为读音审核通过。
- 生成器有请求超时、两路有界并发；全批成功后才发布清单。重跑会校验并复用同参数成品，不强制重调在线服务；切换音色／语速应使用新版本目录。
- 普通网站构建只运行 `audio:check` 检查已提交成品，不调用合成服务、不要求安装 edge-tts／ffmpeg；生成与解码验证才需要这些工具。

### 制作与复核

```bash
npm run resources:prepare
npm run audio:catalog
# 在独立 Python 虚拟环境内安装制作依赖，再运行生成器。
python3 -m pip install -r tools/audio-requirements.txt
python3 tools/generate-stroke-audio.py
npm run audio:check
```

制作环境还需 ffmpeg 和 ffprobe。仓库默认成品可直接构建，无需重新生成；Python 工具不进入浏览器依赖。完整来源：[edge-tts README](https://github.com/rany2/edge-tts)。

## 2026-11-10：“游”笔画漏播修复

用户反馈“横折”无声，进一步确认汉字为“游”。检查发现第 6 笔“横折钩”有独立录音；第 10 笔原字典返回“横撇|横钩”，引擎按未核对歧义保留未知，无法匹配录音。普通“横折”资源的哈希、解码和音量检查正常，口／日／田页面播放也能启动对应录音。

按上表核对原页后，仅增加“游”零起索引 9 的“横撇”修正，复用现有已确认录音；不全局替换歧义候选，也不改变第 6 笔或其他字的判定。未知候选仍保留“暂缺”，不为了有声而编造名称。

验证：旧构建的浏览器回归稳定复现“游”仅启动 11 段录音，缺第 10 笔；同一检查在修复后的生产构建通过，实际解码／启动的 12 段音频哈希与对应笔画清单逐项一致，并确认“口”3 笔不回归。98 项 Node 测试、48 字／233 笔样本、构建及 6 组真实断网回归通过，无未处理页面异常。测试不代替用户真机听感确认。

可用 `node test/browser-stroke-speech.mjs <CDP地址> <站点地址>` 重跑；默认使用隔离 CDP `http://127.0.0.1:9224` 和预览 `http://127.0.0.1:5189/`，在独立上下文中检查，不使用日常浏览器数据。已保存的离线字单需联网刷新版本并主动更新离线包，以获得新名称映射及所需录音。
