## 1. 目标和顺序

**先将现有 Web 做到稳定、流畅、好用，并补齐必要功能；通过验收后再决定 App 平移范围和手机能力扩展。**

本计划承接 [K12 长期产品设计](K12产品设计与Web重构规划.md)中的 Web 体验、技术重构与验收内容，作为当前 Web 工作的统一依据。K12 文档保留人群、产品方向和功能选择池。

顺序确定为：

1. **UI 与交互重设计先行**：明确页面结构、主要动作、播放语义和异常反馈；制作可交互原型，作为后续重构基础。
2. **建立可靠的资源底座**：自托管字形数据与预生成笔画录音，统一资源版本和加载方式。
3. **重建播放调度**：一个控制器统筹字、笔画、动画、音频、暂停与取消，解决乱序、跳动和同步。
4. **补齐必要功能并验收**：单步定位、重播、批量导航、查询历史等，完成跨浏览器和弱网验证。
5. **再评估 App**：按 Web 的实际稳定能力建立迁移清单，另行探索相机、语音输入、系统分享、手写笔和离线包。

UI 先行是先完成结构、行为与可验证原型，再由同一套行为规则指导底层改造。原型不沿用旧播放逻辑来证明可靠性，也不因为界面完成就宣称稳定。

## 3. UI 与交互重设计：第一阶段

### 3.1 体验原则

- 查询与播放分开：输入后点“查询”，先看完整字形，再主动播放。回车提交查询，并处理中文输入法组合输入。
- 一次聚焦一个字：固定主画布，多字采用导航切换；播放时主页面不自动滚动或弹跳。
- 操作位置稳定：播放、前后笔、前后字始终在固定区域；文字变化不引发明显布局变化。
- 首屏能完成核心任务：不先选年级、不要求登录；高级选项折叠。
- 界面可完全重做：不受现有渐变、卡片、阴影和 bounce 动画约束；默认低干扰，重点突出字形和当前笔。

### 3.2 布局与页面

按用户反馈改为两个视觉状态，去掉三栏式说明面板：

- 输入前：空白页仅突出居中大输入框，以“输入汉字或词语”作最基本提示；不预填、不展示空画布或展开设置；右上角菜单始终可用。
- 查询后：输入框缩小，突出大字画布。当前字只出现在页面正中画布中，已看字在左、待学字在右同排排列；超出页面宽度的部分裁切，在两侧页面边缘渐隐。手机也保持画布居中，不为展示所有小字而挤压或偏移画布，不让整页横向溢出。
- 切字：选中的候选字轻量移入画布，后续候选依次前移；已看字通过上一字返回，重复字按序号区分。最后一字时队列自然为空。
- 主界面只保留播放、前后笔与简短进度；生字本、节奏、速度、语音、轮廓和整组操作收进右上角侧边抽屉。取消逐笔编号列表及重播本笔入口。正常状态不反复显示指导句，异常时才提示原因与恢复方式。
- 输入框下显示最近 10 条查询历史，最新在最左，重复查询移到最左；点击直接复查，本地保存并提供清空。
- 过渡动画独立于播放状态，连点切字时取消旧过渡；尊重减少动态效果设置，不支持动画时直接更新。

```text
输入前（右上角菜单 ☰）
                [ 输入汉字或词语……        查询 ]

查询后（右上角菜单 ☰）
                [ 输入框（缩小）          查询 ]

       ┌──────────┐
… 上个字 │   当前字   │ 下个字   下个字 …
       └──────────┘
            ‹ 1 / 6 ›
          第 N 笔 · 名称
       上一笔   播放   下一笔
```

### 3.3 明确操作语义

| 动作 | 约定行为 |
|---|---|
| 查询 | 固定一份结果快照；当前字优先加载，先显示完整字形；输入框后续编辑不改变正在播放的结果 |
| 播放 | 从选定位置开始；整组模式按字单顺序继续，单字模式不擅自跳到下一字 |
| 暂停／继续 | 暂停保留已完成笔画；中断笔在继续时从该笔起点连同录音重播，后续不重播整字 |
| 上一笔／下一笔 | 先暂停；移动一笔并展示截至该笔的完整结果，不自动发声，点击播放可继续 |
| 重播 | 保留字与设置，从当前字首笔重播；另提供“整组从头播放” |
| 切字 | 可点前后字或在大字格左滑下一字／右滑上一字；首尾不循环，练习模式停用滑动。取消当前播放和录音，显示目标字完整字形；整组自动切字与手动切字采用同一取消规则 |
| 变速 | 当前笔保持原速度，下一笔使用新速度；录音正常语速，不跟随极端动画倍速 |
| 关闭语音 | 立即停止当前录音，动画继续；开启后从下一笔开始，避免补播旧名称 |
| 清空 | 先取消任务并释放资源引用，再清空结果；保留用户速度、格线与语音设置 |
| 后台／恢复 | 进入后台自动暂停；回来不自动发声，用户继续时重播中断笔 |
| 播放完成 | 保留完整字形，标记完成，主按钮显示“重播” |

笔画状态明确区分“已展示到第 N 笔”和“下一笔待播放”，避免定位后跳一笔或重复一笔。设计稿和控制器共用这些定义。

### 3.4 原型与交付

先完成结构线框，再做一个主视觉方向和桌面／平板／手机三种尺寸的可交互原型。W1 已按反馈改为输入框／画布两阶段重心与横向候选队列，详见交互原型记录。用固定样例数据模拟流程，覆盖空白、加载、完整字形、播放、暂停、完成、单字失败、音频失败和混合成功字单。实现前梳理原有入口的功能对应关系，避免新界面漏掉多字连播等既有能力。

原型任务：输入词语后查第 N 笔、切换单字、整组播放中暂停、跟写时重播本笔并继续、某字加载失败后继续查看其他字。验证按钮含义是否清楚、操作次数是否合理、关键区域是否被键盘遮挡。

视觉采用浅色底、深色字和单一强调色；当前笔、格线和轮廓保持可辨。触控区域建议至少 44×44 CSS px；提供可见焦点、真实标签、键盘操作和减少动态效果选项。状态不能只依赖颜色，逐笔变化不应造成连续高频读屏提示。

## 4. 语音方案：edge-tts 预生成，运行时播放录音

### 4.1 方案决策

采用**离线生产资源、在线按需播放**的方式：开发／内容制作阶段用 edge-tts 把审核后的笔画名称生成独立录音，随网站资源发布；用户浏览器只下载、缓存和播放，不实时调用 edge-tts，也不依赖系统是否安装某个中文语音包。

edge-tts 是调用在线合成服务的工具，预生成并不表示合成过程离线。其 README 提供 `--write-media` 等媒体生成能力；生成工具不进入网站运行时依赖。来源：[edge-tts 项目](https://github.com/rany2/edge-tts)。

以实际字库的规范笔画名称清单生成资源，不先假设一定是 28 或 32 种。不同汉字复用同一名称录音，不按每字每笔重复生成。名称缺失或有争议时先标为未知，不生成“点”兜底录音。

### 4.2 制作与管理

1. 从审核过的笔画名称表生成清单，分配稳定 ID，名称别名显式映射到规范 ID。
2. 选定普通话音色和语速，小批试听后固定生成参数。特别核验短名称、复合笔画名的读音、完整性和自然停顿。
3. 批量生成独立 MP3；检测文件可解码、非空、时长正常、无截断，人工听完全部名称；处理首尾多余静音并保留必要余量。
4. 生成 manifest，记录名称 ID、文字、文件路径、音色、语速、实际时长、内容哈希与版本。
5. 保留已审核成品，重新生成先产出新版本，不在网站请求或部署构建时强制重新合成。工具或上游服务暂不可用，不影响既有音频发布。

建议资源布局为 `public/audio/strokes/<version>/` 和版本清单；具体文件名按稳定 ID，不以中文名称的隐式拼接作为唯一映射。生成脚本后续单独提供，记录使用方式与资源来源。

### 4.3 浏览器播放与降级

- 先准备当前字所需的去重音频，再预取邻近字；不会每播一笔都新建无管理的音频任务。
- 只有一个受控制器管理的音频播放器／上下文；每个回调携带会话与笔画身份，结束、失败、取消都必须结算等待。
- 首次点击播放时启用音频；本地 MP3 同样受有声自动播放策略约束，不能承诺“预生成后任意时刻自动有声”。遇到阻止时显示“点击启用声音”，同时允许静音继续。参考：[MDN 自动播放说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。
- 音频未下载、解码失败或启动超时：给出一次明确提示，切为当前会话静音播放；可重试声音，不无限等待，也不在恢复后补播过期音频。
- 浏览器 speechSynthesis 不作为隐式兜底，以免再次引入不可控音色、事件与时序；以后确有需求再作为独立可选能力评估。
- 页面录音播放不等于完整离线：只有缓存已覆盖的音频与字形可在断网下使用；完整离线包是后续功能。

## 5. 字形资源：自托管为基线，CDN 作为可选加速

### 5.1 方案决策

**首个稳定版本不以“自动选中最快公共 CDN”为前提。** 将目标字库的数据文件部署到站点静态资源服务或受控对象存储，首选同源路径；这不要求新增动态后端。CDN 可在受控资源前加速，源站始终保留可用副本。

当前有 48 个本站 JSON，只能作为起点。先盘点完整候选字库、实际体积、资源来源与许可，再确定首发覆盖范围；生成支持字符清单并在界面解释缺字。目标是目标字库完整自托管，而非长期让绝大部分常用字回落到公共 CDN。

### 5.2 统一加载流程

1. 校验字符支持情况，读取 manifest 中的固定数据版本；不使用漂移的 `master` 资源作为生产基线。
2. 命中内存或浏览器缓存则复用；同字同时请求去重，保留重复字的独立播放位置。
3. 首选受控资源路径；单次请求有超时、取消和错误分类，不重试确定的缺字或坏数据。
4. 资源成功后校验 JSON 结构、strokes 与 medians 数量、名称数量及必要的版本信息；校验失败不得作为已就绪字继续播放。
5. 仅当前字就绪即可查看和播放，其余字后台有界并发预取。单字失败不阻塞已就绪字；整组播放跳过失败项时明确提示，完成状态不能掩盖失败。
6. 预加载、HanziWriter 自定义 loader 和播放全部使用这一份数据，不再让静态 loadCharacterData 暗中绕回默认 CDN。官方支持自定义加载：[HanziWriter 文档](https://hanziwriter.org/docs.html)。

采用版本化 URL 与适合静态文件的缓存响应头，版本清单采用可更新策略；发布时先上传完整资源再切换清单，旧版本保留回退窗口。记录资源命中、耗时、错误类型与加载来源，诊断信息无需记录用户输入全文。

### 5.3 CDN 自动选择的取舍

自动选择只能基于当前请求的实际可达性和耗时，不能靠 IP 地区或浏览器网络类型推断。若后续数据表明自托管跨网络性能仍不足，再评估：

- 对少量受控候选源以真实、等版本的小资源做有超时的探测，综合时延、失败率和返回数据有效性。
- 选定源在短期会话内保持稳定，连续失败才切换；避免每个字都对全部源测速。
- 所有来源提供相同版本和校验信息；错误源不得污染共享缓存。自托管源可直接访问，且在加速源失败时自动回退。

首轮不做复杂公共 CDN 竞速。先用不同网络实测自托管、受控 CDN 和回源路径，再判断自动择优是否值得增加复杂度。

## 6. 动画与语音：统一播放控制

### 6.1 时序与状态

查询结果保存不可变字序、字形版本、有序笔画和音频 ID。一个播放控制器持有当前会话 ID、字索引、已完成笔数、活动笔、模式和取消信号。单字播放、整组播放、重播本笔全部经过同一入口，禁止各自开循环竞争画布。

```text
空闲 → 加载当前字 → 就绪 → 播放 → 完成
                         ↕ 暂停
任意状态 → 取消旧会话 → 新查询／切字／清空
```

暂停可保留同一查询会话，但必须作废当前执行任务；取消时停止音频、动画与可取消延时。每次 await 返回后核验任务身份；已经取消的回调不得更新进度、清理新画布或触发下一笔。

### 6.2 同步规则

| 节奏 | 每笔行为 | 下一笔条件 |
|---|---|---|
| 快速看 | 连贯动画，默认关闭逐笔名称录音 | 本笔动画结束＋短间隔 |
| 听讲解 | 音频准备好后，同一调度步骤启动录音与动画；名称固定显示 | 两者都结束＋配置间隔 |
| 跟着写 | 本笔示范与可选录音结束后暂停 | 用户点“继续”；“下一笔”仍只静态定位 |

音频启动失败不能阻止整个播放任务；动画报错则停止该字并提示重试，不继续靠计时器猜测进度。音频较长时，动画结束后保持当前笔高亮，直到本笔语音结束，避免提前播下一笔的名称。

首阶段承诺的是**笔画级对应和可测量的起始偏差**，不要求笔画轨迹跟着录音音节变形。普通媒体元素或解码缓冲音频的选择，通过小原型验证首播延迟、取消行为和移动 Safari 兼容性；如需进一步压缩启动偏差，再采用统一音频时钟等方案，避免先重写引擎。

### 6.3 避免乱序与跳动的约束

- 显示当前第 N 笔必须与同一任务的路径和录音一致，动画未完成不提前提交已完成笔数。
- 清空、切字、切模式先取消旧任务，再渲染；背景加载可以缓存数据，但不得直接改动活动画布。
- 复原到第 N 笔应由同一适配层按有序数据生成前缀，保证可重复且不触发声音。
- 固定主画布尺寸区域，不随名称长短重排；移除播放导致的 scrollIntoView、bounce 和轮廓闪烁。
- 对锁定 HanziWriter 版本核验暂停、取消、单笔速度参数及返回结果；目前 animateStroke 的 duration 传参不能直接当作已受支持的调速机制。

## 7. 实现边界与职责

保留 Vite、原生 JavaScript 和可复用引擎，暂不因重构引入 UI 框架或动态服务。职责拆分以当前需求为界：

| 职责 | 内容 |
|---|---|
| 字数据服务 | 受控来源、缓存、请求去重、超时、版本与一致性检查 |
| 音频资源与播放器 | manifest、预加载、音频启用、播放／取消／失败结算 |
| 播放控制器 | 唯一任务、字笔位置、教学节奏、状态迁移与错误恢复 |
| HanziWriter 适配 | 字形显示、前缀恢复、单笔示范、引擎 API 边界 |
| UI 与本地设置 | 搜索、导航、画布、控制、提示；历史和收藏可删除 |

先定义资源记录与播放事件契约，再接 UI，避免把状态判断散落在按钮回调。后续 App 可以复用资源和规则，但不提前抽象跨平台运行框架。

### 8.1 验收标准

以下数值为初始目标，尚非实测；先固定设备、字集、网络条件与计时定义，再报告 p50／p95。无法达到时记录原因并调整方案，不能隐藏失败。

- 缓存字查询到可操作 p95 ≤ 500ms；热缓存切字 p95 ≤ 300ms；点击可见反馈 p95 ≤ 100ms。
- 暂停／切字后 200ms 内旧动画和音频停止推进；被取消任务不得再开始下一笔或写入新状态。
- 听讲解模式在音频已预加载、前台运行条件下，测量实际可听起音与画面起笔偏差，初始目标 p95 ≤ 150ms；同时测试冷缓存，不以 play() 调用时间代替实际起音。
- 字形请求初始预算：单源 3 秒、当前字总计 8 秒；超时转为明确失败状态，其他字可用。音频加载、启动和结束等待也设有界预算，以 manifest 时长加余量检测缺失结束事件。
- 连续播放至少 20 字，包含重复字与复杂字，路径、名称、录音逐笔一致；异常字不能被计为成功完成。
- 测试播放中连点、反复暂停继续、切字、改输入、定位、清空、切速度／节奏／声音、整组完成后重播；无并行声音、跳笔或旧任务回写。
- 断开公共 CDN 不影响已部署目标字库；模拟本站 404、超时、坏 JSON、名称数量冲突、坏音频和音频被阻止，均能恢复或明确降级。
- 覆盖冷缓存、热缓存、弱网和断网。未实现完整离线包前只承诺实际缓存资源，不宣称离线全覆盖。
- 320px 手机到桌面无水平溢出；软键盘、横竖屏和平板分屏下主要操作可达，主画布不跳动。
- 当前设备矩阵：桌面 Chrome／Edge／Firefox，iPhone／iPad Safari，Android Chrome（2026-11-08 用户将桌面 Safari 移出本轮，iOS Safari 继续保留）；实施时记录实际版本与设备，至少选代表性真机，不能仅靠缩放桌面窗口认定移动端通过。
- 目标字库路径、笔数和名称对应关系有自动检查；未知名称不再静默变“点”。内容审核与技术校验分开记录。

### 8.2 自动验证与发布

npm test 仅测试页面使用的 v3，不保留 v2 测试入口。W0 已修正失败判定，字级不匹配、缺失 fixture 或数量不一致均返回非零；旧算法源码暂保留。W2 已核验并处理 W0 的 10 字差异（含 5 处旧预期修正），48 字回归通过；具体依据见 [资源与内容核验](Web资源与内容核验.md)，不外推为全库准确。

增补有价值的控制器状态测试，覆盖取消后回调、失败结算、暂停恢复与位置边界；用可控音频／动画适配器构造竞争时序，再用浏览器验证真实媒体行为。资源检查验证清单、文件存在、版本一致与可解码性，不把能请求到文件当成内容正确。

UI 用少量端到端流程覆盖查询、定位、重播、整组播放和失败恢复。涉及布局和声音的验收必须保留人工浏览器／真机验证。生产构建要验证 dist 中的字形、录音、manifest 及路径，修复单字路径返回 SPA HTML 的伪成功。

按阶段提交可审查变更，不在新旧控制器间混用状态。发布前保留可回退的构建及资源版本，确认缓存刷新策略；实际发布在用户授权范围内另行执行。

## 附录：现有代码诊断（迁自 K12 设计稿）

本轮未进行浏览器与真机性能测试。以下是代码可以确认的机制及待验证的影响，不是已经测得的卡顿结论。

| 发现 | 代码依据 | 可能的体验影响 | 重构方向 |
|---|---|---|---|
| 全部加载完才开始整组播放 | renderCharacters 等待 Promise.allSettled | 一个慢字拖住整组首播 | 当前字优先，其他字后台预取，独立失败 |
| 多数据源串行、无显式超时取消 | loadFromCDNs 的 fetch 循环 | 慢源可能长时间占住加载状态 | 自有版本化资源、请求超时、取消与缓存；备用源受控 |
| 动画前再次用静态方法取数据 | 两条播放路径调用 HanziWriter.loadCharacterData，未传相同 loader | 可能走默认 CDN，首轮本站加载收益不能确保复用 | 加载一次，字形、名称与播放共用数据记录 |
| 语音先结束，动画才启动 | await speech.speak 后 await animateStroke | 每笔“先说再写”，节奏割裂且变慢 | 明确三种教学节奏，统一时间控制 |
| 正常速度仍有每笔一秒间隔 | speedSettings[3].delay 为 1000 | 多笔字观看耗时长 | 按节奏设置默认值，实测后调参 |
| 速度动态控制存在疑点 | animateStroke 传 duration；官方文档该方法未列此选项 | 切换速度是否真正作用于当前动画需核实 | 对锁定依赖版本检查受支持参数，再测试切速 |
| 单字点击没有统一任务状态 | animateSingle/runSingleAnimation 与 playAll 分离 | 连点、打断、恢复可能互相影响 | 所有入口走一个播放控制器和可取消任务 |
| 暂停主要停布尔标记和动画 | stopAnimation；语音、delay 后缺少一致的任务校验 | 停止后旧异步步骤仍可能继续更新 | 每次等待后核验任务身份，定时等待可取消 |
| 播放时读取可变输入框 | 播放函数从 dom.input.value 按索引取字 | 用户修改输入后显示对象可能不一致 | 查询结果不可变，编辑输入不改变当前会话 |
| 自动滚动与卡片跳动叠加 | 每字 scrollIntoView；active bounce | 观看位置跳动、难以聚焦 | 固定主画布；仅导航选中态更新 |
| 移动端样式被后置样式覆盖 | 同等优先级 !important：80/70px 在前，160/150px 在后 | 移动端预期缩放失效；网格可能容纳不足 | 合并尺寸规则，先移动端，再按断点增强 |
| 清空先丢掉实例引用 | clearAll 先 writers.clear，再 stopAnimation | 取消函数无法再遍历旧实例 | 先取消、释放，再清空引用和视图 |
| 查询与播放共用一个主动作 | handlePlay 同时决定加载、恢复和播放 | 状态难预测、已加载也可能看不到完整字 | 查询、示范、练习分别建模 |
