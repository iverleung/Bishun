## 处理与版本

`tools/import-user-audio.mjs` 是本次一次性导入工具，目标 v2 目录已存在时会拒绝覆盖，避免意外替换已审核资源。处理步骤：

1. 验证原始导出清单、稳定身份、位置及文件对应关系。
2. 用 ffmpeg 检查解码、时长和整体平均／峰值音量。
3. 对首尾低于 -55 dB 的静音进行裁剪。
4. 使用 EBU R128 loudnorm，目标 `I=-16`、`TP=-1.5`、`LRA=11`。
5. 转为单声道、24,000 Hz、48 kbps MP3；计算成品时长、字节数和 SHA-256。
6. 全部成品标为 `pending-listening`，不继承 v1 的人工试听结论。

当前运行时使用：

- `resources/reading-audio-v2-catalog.json` 与 `public/audio/readings/v2/`；
- `resources/stroke-audio-v2-catalog.json` 与 `public/audio/strokes/v2/`。

原 v1 文件、清单和审核记录没有覆盖或删除。拼音 ID 与成品内容哈希绑定，笔画 ID 继续与规范名称绑定。来源说明见各 v2 目录的 `SOURCE.html`。

## 覆盖与验证

教材 2,983 个不同汉字的字典候选覆盖：2,940 字全部候选有录音，18 字部分候选有录音，25 字没有任何候选录音。覆盖 1,141 个教材候选音节，仍缺 17 个；这 17 个正是上述质量排除项。该统计不表示已按教材语境审定读音。

- `npm run --silent audio:user:check` 校验 v2 清单、稳定身份、排除／未录范围、成品文件字节和 SHA-256。
- 1,499 个 v2 MP3 全部通过 ffmpeg 解码，时长元数据最大误差 1 ms。
- 原 v1 校验继续运行，防止历史资源被无意改变。
- 播放端 v2 清单和 URL 校验、NFC 查询、覆盖快照及取消规则纳入现有 Node 回归。

仍需用户分批试听 v2；确认时应把审核结论绑定到具体成品 ID 和 SHA-256，不能整批标记为已审核。17 个排除项需要在录音页重录后另行导入。
