# Web 触控兼容修正

日期：2026-11-08。用户 iPhone 反馈与候选修正，真机复测尚未确认。

## 反馈与边界

用户确认点击“全屏书写”后已进入专注布局，但 Safari 地址栏仍在。截图进一步表明当前为普通笔顺演示、3 字查询、第一字暂停在第 1/4 笔，不是单字查询或屏幕练习。因此，左右滑动切字本应可用。

专注布局已经生效，不把浏览器栏保留当作布局未开启。本次仅把入口名称改为“专注模式”，继续在浏览器支持时尝试原生全屏，不承诺所有平台隐藏浏览器 UI；保留原有专注布局、退出按钮及菜单。平台背景参考 [WebKit 的 iPhone 全屏问题记录](https://bugs.webkit.org/show_bug.cgi?id=328773)，不据此推断用户系统版本的全部能力。

## 兼容处理

此前触控仅走 Pointer Events，且窗口任何 resize 都清除手势。截图不能确定具体哪一个 Safari 事件丢失；本次针对这两个兼容风险调整，不宣称已经从真机事件日志确定根因：

- 单指触控使用 Touch Events 直接读取坐标，不再依赖 SVG Pointer Capture。鼠标／笔继续使用 Pointer Events，触摸的并行 Pointer Events 不参与切字，避免重复触发。
- 非被动 touchmove 仅在明确横向意图后阻止默认动作；结束时沿用原距离／方向阈值。纵向拖动放行，多指／取消不切字，保留页面滚动与缩放的能力。
- 仅窗口宽度变化才清除手势；浏览器栏或键盘引起的同宽 resize 不再直接中断滑动。进入后台、菜单、练习、新查询与原有上下文校验仍然取消过期手势。
- 练习模式保持手写输入，不响应切字，新增触摸处理在练习中不阻止引擎事件。CSS 对 pan-y 提供独立声明作为组合值的兼容兜底。

## 验证

- 48 字／233 笔样本、61 项 Node 回归通过；新增触摸／指针双流去重、触摸 PointerCancel 不误取消、方向与默认动作、多指／查询／练习取消检查。
- 四入口生产构建与资源／录音前置检查通过；修改文件语法及 diff 检查通过。
- 用户授权 CDP 9223 的 Chrome 156.0.8078.81，原生触控专项 8 组通过，包含左右切字、短拖动、纵向滚动、取消播放和练习互斥，未捕获异常为 0。
- 新增 `browser-touch-focus.mjs` 的 6 组检查通过：不支持原生全屏时仍有专注画布和退出入口；同宽 resize 事件插入真实触摸流后仍切字；注入触摸 PointerCancel 后 Touch Events 仍可完成切字；双向与短拖动边界；退出不自动播放；多字查询中原生触摸写完十的两笔且不误切字。
- 全量练习复跑在提示阶段遇到测试页 `visibilityState=hidden`，UI 已暂停并提示“提示未完成，可继续练习”，该轮未完成，不能计为通过。针对新增处理的短程原生手写检查已单独通过。

以上是 Chrome 触控注入；全屏能力、同宽 resize 与 PointerCancel 是为了检查分支而明确模拟，不是 Safari 地址栏事件或实体手指体验。iPhone 真机左右滑动仍待用户刷新验证。完整结果见 [验收记录](验收记录/ios-touch-compat-2026-11-08.json)。
