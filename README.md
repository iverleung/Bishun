# 汉字笔顺工具（Bishun）

面向小朋友的汉字笔顺动画 Web 工具，支持多字顺序播放和笔画名称播报。项目使用 Vite、原生 JavaScript ES Modules 和 CSS，目前没有 UI 框架或动态后端。

## 访问入口

- `/`：新版默认首页（本地候选版，尚未部署）。
- `/preview/index.html`：原预览地址，自动转到新版，保留查询参数与片段。
- `/print/index.html`：独立练习纸预览，由新版打印入口携带汉字及可选教材课题打开。
- `/record/index.html`：独立手机拼音录音工具，录音仅保存在本机浏览器，可导出 ZIP。
- `/legacy/index.html`：仅保留历史地址兼容，新版不再提供旧版导航入口。

候选版范围、入口验证和发布边界见 [首页切换记录](docs/Web首页切换候选版.md)。

## 开发与构建

依赖范围见 [package.json](package.json)，锁定版本见 [package-lock.json](package-lock.json)：HanziWriter ^3.7.3、cnchar ^3.2.6、cnchar-order ^3.2.6、cnchar-radical 3.2.6，以及开发依赖 Vite ^6.4.1。

```bash
npm ci
npm run dev
```

生产构建与本地预览：

```bash
npm run build
npm run preview
```

`predev`／`prebuild` 会从锁定的 `hanzi-writer-data@2.0.1` 开发依赖生成全量候选字形，需安装开发依赖后启动或构建。构建输出为 `dist/`，可部署到静态托管服务；不再构建离线资源包；`offline-sw.js` 仅为旧安装的退出兼容端点，不提供缓存服务。`public/` 中的字形资源会复制到构建输出。构建脚本先清理生成目录 `dist/`，对暂时性目录占用最多重试 3 次，失败会中止构建。预览命令需要先构建；未构建的源代码依赖 Vite 解析 npm 导入，不能直接用普通静态文件服务器运行。目前根目录没有 `deploy.sh`。

## 手机拼音录音

打开 `/record/index.html`，按住“按住录音”按钮，读完当前拼音后松开，录音自动保存在本机 IndexedDB；可原地试听、重录或进入下一项。“下个未录”跳到下一段缺口，“管理与导出”支持按拼音跳转和导出全部录音 ZIP（含 `manifest.json`）。刷新后按 `reading` 恢复当前位置（兼容旧数字下标）与已录进度，不上传音频。页面初始化时提前申请并准备麦克风，连续录音复用音频流以减少启动延迟；重录时旧文件保留到新录音成功保存；后台切换丢弃尚未完成的录音并释放麦克风，回到前台后重新准备。

录音页在拼音下方最多显示 3 个清单例字，无例字时保留固定高度。可在本机分析解码、静音、有效声响度和峰值，按“待复查”筛选并人工标记重录；技术结果不代表发音审核通过。“自动试听”可连续播放已录或待复查项目，播放中按住录音会停在原拼音重录，保存后原地复查新录音；试听时释放麦克风以避免手机音频路由影响响度判断。详见[录音页自动检查与连续试听](docs/录音页自动检查与连续试听.md)。

手机浏览器通常要求 **HTTPS** 才开放麦克风；iOS 使用 Safari 导出时音频格式通常为 M4A/AAC，Chrome 通常为 WebM/Opus，具体以 ZIP 清单为准。清除网站数据会删除浏览器内录音，应定期导出备份；页面本身不承诺跨浏览器迁移或云端同步。

## 当前功能

运行 `npm run dev` 后直接打开终端显示的地址 `/`（默认 `http://localhost:5173/`）；生产构建同样以 `/` 为新版入口。原预览链接继续可用，旧版保留为独立页面。W4 资源故障检查、偏好与字单能力见 [稳定性验证记录](docs/Web稳定性验证.md)。

新版保持已确认的精简界面：输入前突出输入框；查询后隐藏品牌、完整输入框和历史，只保留约 48px 的单行工具栏及居中的大字画布，两侧候选在页边渐隐。点顶部“搜索图标＋当前字组”打开搜索面板，输入与历史按需出现；打开时暂停演示／练习，取消保留当前进度，提交后收起且不自动播放。正常结果字格随视口调整，最大 440px；细则见 [查询工具栏](docs/Web查询工具栏.md)。支持最多 20 个 Unicode 汉字，保留词序与重复字；历史最新在左，支持复查与清空。

已接入本站 9,574 字候选字库、HanziWriter 真实轨迹动画和 31 份预生成笔画录音（原 30 份已确认，新增“竖折折”待试听）。统一播放流程，默认开启声音和连续播放，声音开关可关闭笔画录音，不再选择播放节奏。主页面保留播放、上一笔／下一笔和前后字；按编号定位与重播本笔入口已移除。菜单中的“播放设置”默认展开，仅保留声音、连续播放及慢／正常／快三档速度；示范固定显示米字格和轮廓。连续播放从当前字到末尾，整组结束后主按钮重播会回到首字；“重播这个字”仍显式从当前字开始。暂停保留完成笔，中断笔继续时从笔首重播；切字、新查询、清空和后台暂停共用取消规则。录音失败时提示并静音继续，字形失败可重试或切字。

大字格左滑切下一字、右滑切上一字，重复字按原顺序切换，到首尾不循环；纵向滚动和双指缩放保持原生能力。练习模式不响应切字手势，避免将手写笔画误判为导航。右上角菜单以侧边抽屉打开，生字本展开不占主页面高度；选清单、进入打印会收起抽屉，设置调整保持打开。打开菜单暂停当前演示或练习，关闭不自动继续；支持关闭按钮、遮罩及 Esc。选清单后聚焦播放控制，避免弹出输入键盘。触控使用独立 Touch Events 路径，横向意图明确后才阻止浏览器默认手势，鼠标／笔使用 Pointer Events；同宽度的窗口高度变化不再清除滑动。独立专注模式已取消，直接使用默认居中画布。只保存声音、连续播放和速度；旧五档速度收敛到中间三档，旧播放节奏、格线／轮廓开关不再生效。恢复默认设置不清空历史与收藏。

右上角菜单只提供一个“收藏”入口：单字直接保存，多字时选择当前字／这组字，取消不写入。菜单内折叠的“我的生字本”可复查、管理和备份清单：支持命名、编辑、上移／下移及删除，最多 30 条，每条最多 20 字，保留字序与重复字。管理状态才显示编辑、排序、导入和导出，空生字本也可点“管理”导入备份。JSON 导入先预览可导入、重复、无效与超额条目，确认后仅追加有效内容，不覆盖旧清单或静默淘汰；导出仅含清单与名称。备份不超过 100 KB、500 项，名称最多 40 字。旧收藏读取兼容，首次修改写入独立 v2 存储，旧 v1 数据保持原样；清空历史和恢复默认不删除收藏。存储失败提示仅本次打开有效。

“打印练习纸”进入独立 A4 纵向预览，支持当前字／整组、米字格／田字格、三档格子大小和每字 1—3 行；每字包含范字、两格浅色描红和空白练习区。浏览器打印界面可在支持的设备另存 PDF；打印隐藏操作控件，附完整字形许可页。缺字或加载失败需重试或明确移除后打印；许可文件加载失败阻止打印。返回查字恢复原组，不自动播放。

## Ark 拼音候选音频

`tools/generate-ark-reading-audio.py` 使用 Ark `seed-tts-2.0` 的 HTTP 单向接口，从 [拼音音节合成列表](docs/拼音音节合成列表.json) 生成待试听的 MP3；默认只取前 10 项，输出到 `tts/ark/`，不修改网站现有录音。密钥从进程环境的 `ARK_API_KEY` 或项目 `.env` 读取，工具不会打印密钥。已有文件默认拒绝覆盖，`--overwrite` 需显式指定。

```bash
npm run audio:ark -- --dry-run                         # 只预览前 10 项，不读取密钥、不联网
npm run audio:ark -- --start 11 --limit 10            # 生成清单第 11—20 项
npm run audio:ark -- --reading à --text 'à=啊！'       # 指定读音及发音文本
npm run audio:ark -- --limit 5 --normalize            # 同时归一化到 -16 LUFS，需要 ffmpeg
npm run audio:ark -- --all --output-dir tts/ark-all    # 显式生成完整清单
```

可用 `--speaker`、`--speech-rate`、`--sample-rate` 和 `--timeout` 调整合成参数，完整选项见 `python3 tools/generate-ark-reading-audio.py --help`。未指定 `--text` 时使用对应 `characters` 的第一项，**不代表读音已验证**；多音字和轻声应先人工确定文本并用 dry-run 核对。`--normalize` 可写为目标值，例如 `--normalize -18`。生成成功仍需逐段核听声母、韵母、声调、轻声及尾音。

CLI 单元测试不访问密钥或网络：`python3 -m unittest discover -s test -p 'test_ark_reading_audio.py'`。

## 阿里云拼音候选音频

`tools/generate-aliyun-reading-audio.py` 使用智能语音交互的 `NlsSpeechSynthesizer` 和 [SSML 拼音音素标记](https://help.aliyun.com/zh/isi/developer-reference/ssml-overview)，把清单的调号转换为 `1—4` 声及轻声 `5`，例如 `ǎ → a3`，默认生成前 5 项到 `tts/aliyun/`。例字只作为 SSML 承载文本，读音由 `<phoneme alphabet="py" ph="...">` 显式指定；生成结果仍需试听，不自动替换网站录音。

Python 依赖安装到项目 `.venv`，官方 SDK 固定提交记录在 `tools/aliyun-audio-requirements.txt`：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/aliyun-audio-requirements.txt
npm run --silent audio:aliyun -- --dry-run             # 不读取配置、不加载 SDK、不联网
npm run --silent audio:aliyun                          # 默认 xiaoyun，生成前 5 项
npm run --silent audio:aliyun -- --reading lǜ          # 指定清单读音
npm run --silent audio:aliyun -- --start 6 --limit 5   # 生成后续范围
```

程序从进程环境或项目 `.env` 加载 `ALIYUN_ACCESS_TOKEN`，以及 `ALIYUN_NLS_APP_KEY`（兼容 `NLS_APP_KEY`），不会打印配置内容。可用 `--voice`、`--speech-rate -500..500`、`--sample-rate`、`--timeout` 和 `--overwrite` 控制生成；已有文件默认拒绝覆盖，任一请求失败后停止后续请求。工具只接受单音节条目；清单中 `túnwǎ` 这类一个例字对应多个音节的特殊项需另行处理，不会拼造 SSML。接口用法见[语音合成 Python SDK 文档](https://help.aliyun.com/zh/isi/user-guide/sdk-for-python-1)。单元测试使用模拟 SDK，不访问密钥或网络：`python3 -m unittest discover -s test -p 'test_aliyun_reading_audio.py'`。

## 汉字数据与内容

W2 新增 `/characters/2.0.1/` 自托管候选字库：9,574 字，原始约 32.2 MB，按字请求。对规范表 8,105 字实测覆盖 6,866 字，仍缺 1,239 字，不能宣称全覆盖。`src/data/character-store.js` 已实现同源加载、缓存、去重、超时与结构校验，已接入新版，旧首页仍使用原有入口。使用 `npm run resources:check` 核对生成资源；完整审计见 [资源与内容核验](docs/Web资源与内容核验.md)。


旧首页字形数据优先从 `public/hanzi-writer-data/` 加载，目前包含一批测试集常用字。未收录的字会依次尝试国内镜像和海外 CDN。新增字形时可在该目录加入兼容 HanziWriter 格式的 JSON，但还应校验路径、笔画数、顺序及名称对应关系。

动画路径由 HanziWriter 数据提供，笔画名称来自 cnchar；两者的对应关系需要核验。新版使用 v3 字典查询，保留的 v1／v2 几何算法不表示已支持用户手写识字。笔画分类参考 [STROKE_REFERENCE.md](STROKE_REFERENCE.md)，GF0023-2020 规范 PDF 仅作为本地参考资料保留，不随 Git 分发；参考文档本身不等于全字库已完成规范审核。

### 旧版已知限制

- 输入当前采用 `/[^\u4e00-\u9fa5]/g` 过滤，不覆盖全部 Unicode 汉字。
- 暂停主要保存字位置，继续时可能从该字首笔重播，尚未实现可靠的笔画级恢复。
- v3 缺失或未核验的歧义名称显示“暂缺”；已有具体字修正，其余字典结果仍未完成全库教学审核。
- 数据源串行尝试且无显式超时；本站资源覆盖不完整，也未实现完整离线支持。
- 播放阶段会另行调用 `HanziWriter.loadCharacterData`，尚未统一复用预加载数据及自定义来源。
- 语音仍依赖浏览器合成，动画与语音的同步、播放取消及移动端交互需要重构。
- 目前没有屏幕手写练习、拍照查字、拼音释义、教材同步、账号或原生 App。
